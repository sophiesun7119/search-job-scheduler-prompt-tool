# Project scope

Maintain a one-time Markdown skill that generates two self-contained scheduler prompts. Do not expand it into a search runtime, database, or scheduler service.

Keep personal preferences editable in the example profile. Keep real profiles, Sheet bindings, generated prompts and execution reports under ignored local/ or output/. Public fixtures use example.com and fake Sheet IDs. Use relative resource links.

A generated prompt must work without this repository or prior conversation. Keep the two prompts consistent with the shared Sheet contract. Preserve human fields, distinguish unknown evidence, and report incomplete coverage.

Read tests/acceptance-cases.md when available before substantive changes. Validate skill format, resource links and relevant behavioral cases. Review the exact diff and commit message before every push. Never describe a text review as live scheduler validation. Keep development history out of public usage documents.
